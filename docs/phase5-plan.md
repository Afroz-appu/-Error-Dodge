# Error Dodge Phase 5 implementation plan

Phase 5 starts after the validation report is reviewed. Keep the existing local demo available throughout the migration. The production rollout retains an approval record and runs proposed controls in an isolated evaluation until there is an explicitly authorized deployment mechanism.

| Workstream | Implementation | Acceptance check |
|---|---|---|
| Authentication and authorization | Integrate a managed OIDC provider. Derive user and role on the backend. Add viewer, evaluator, reviewer, and admin permissions. Scope run, benchmark, and approval reads and writes to the authenticated workspace. | API tests cover unauthenticated requests, cross-workspace access, role boundaries, session expiration, and protected review actions. |
| PostgreSQL persistence | Add SQLAlchemy repositories and Alembic migrations for runs, investigations, evaluations, proposals, and audit events. Move graph checkpoints to the PostgreSQL checkpointer. Build an explicit, repeatable SQLite data import with count and ID reconciliation. Enforce one decision per proposal with a transactional constraint across API workers. | Run migrations against an empty database and a restored staging copy. Confirm restart and multi-worker review behavior, rollback, and restoration. |
| Deployment | Build Docker images and a local Compose stack with PostgreSQL. Run migrations as a release step. Deploy an authenticated staging build first, configure readiness and liveness checks, and verify model and Chroma storage across restarts. Select hosting after deciding how to serve the embedding model and persist the index. | Clean checkout starts from documented commands. Staging smoke tests cover login, a sample run, benchmark, review, restart, and rollback. |
| Security | Manage secrets in environment or platform secret storage. Configure TLS, narrow CORS, limits on request sizes and evaluation concurrency, log redaction, and CSRF protection where cookie authentication is used. Validate trusted policy provenance and keep tools read-only. | Test client requests from unauthorized origins and users, malformed inputs, burst traffic, storage isolation, and sensitive-field redaction. |
| Dashboard | Add authenticated navigation, incident filters, benchmark comparisons, searchable traces, loading and error states, and audit history. Clearly label synthetic results and show the evaluation dataset, model, and policy version. | Verify keyboard use, narrow and wide layouts, loading and empty states, and the complete incident-to-review workflow in staging. |

Before moving production traffic, rerun the 22 backend regression tests and the held-out suite. Report deviations separately from existing failures, and preserve the raw measurements. Run authenticated Gemini checks only when credentials and a model are configured. Track the sandbox monitor’s negation limitation and expand the validation corpus to unseen policies and real model traces before activating it.

Implementation references. [FastAPI security](https://fastapi.tiangolo.com/tutorial/security/) · [Alembic migrations](https://alembic.sqlalchemy.org/en/latest/tutorial.html) · [LangGraph checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers)
